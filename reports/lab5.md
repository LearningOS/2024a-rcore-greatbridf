# 进程的所有线程退出时需要回收的资源
`trap_cx` `user_stack` `TaskControlBlock` `fd_table` `memory_set`

# 其他线程的TCB可能在什么地方被引用，是否需要回收

1. `timer`处，在`remove_inactive_task`处已经回收了
2. `task_manager`处，在`remove_inactive_task`处已经回收了
3. `mutex` `semaphore` `condvar`的等待队列中，不需要回收，`PCB`释放的时候会随着也直接回收

# 两种`Mutex`实现的区别

上面第一种解锁时不管有没有等待的，都直接解锁，然后再唤醒等待的线程，应该由被唤醒的线程负责将锁再上锁。下面那个只唤醒下一个线程，不解锁，默认下一个被唤醒的线程持有锁。

# 区别可能导致的问题

上面一种方式，如果按lab给出的实现，会导致被唤醒的线程并不持有锁，可以在上锁的地方加上就不会有问题了。

下面一种方式完全按照获取锁的顺序唤醒，如果在`unlock`之后，有另一个线程去获取锁，仍然是之前唤醒的线程会获得锁，另一个线程还要等待。
